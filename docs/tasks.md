# 后台任务机制

这份文档说明「耗时操作」在当前实现里是怎么工作的，以及哪些行为还没有验证。

## 一条规则

写操作在**执行前**就登记成任务，然后才开始副作用。服务端在这段时间内完成，就直接返回
真实结果（200/201）；超过阈值仍未完成，就返回「受理回执」（202 + 任务标识），动作继续在
后台执行。

当前统一登记规则适用于已接入的任务端点，不包括即时终止进程和流式上传、下载。
阈值（默认 5 秒）只决定**这次请求怎么回**，不是执行时限：超过它不会取消已经开始的动
作，也不会让客户端重发。

## 为什么计时放在服务端

前端计时有三个问题：前端「超时」停不住服务端已经开始的活；前端重发就变成第二次执行；
切后台后前端计时直接失效。服务端计时没有这些问题，并且任务从头就在库里。

## 各角色职责

| 角色 | 职责 |
|---|---|
| `shared/task-policy` | 响应阈值、进度落库节流、历史保留条数、并发上限 |
| `shared/api-contract/schemas/tasks` | 任务种类常量、进度/状态/结果契约（按 kind 固定结果结构） |
| `shared/task-targets` | 任务作用域字符串的唯一来源（服务端加锁与客户端记录共用） |
| `server/common/tasks/store` | `task_record` 表；唯一索引保证同 `lockTarget` 只有一个运行任务；展示目标与冲突锁分离；终态只写一次 |
| `server/common/tasks/runner` | 登记 → 执行 → 阈值竞速；同标识复用、异载荷冲突；结果未知不重放 |
| `server/common/tasks/worker-host` | 受控子进程；未能启动为已知失败，异常退出、无结果、畸形结果或中止为结果未知；并发上限 |
| `server/task-worker` | 执行子进程入口；父进程消失则不开始任何动作 |
| `server/tasks/executors` | 子进程侧的 kind → 实现注册表；载荷先过该种类自己的 schema |
| `web/hooks/use-task-action` | 点击立刻 busy；受理后 busy 延续到终态；结果未知只记录标识不重发 |
| `web/features/tasks/*` | 任务中心、任务卡、按种类登记的完成处理、恢复核实 |

## 进度只报真实数字

进度来自**已经确认处理完**的事件：扫描按已解析的 stat 结果计数，文件复制在每次
分块写入返回后增加字节，整文件结束后增加条目数；删除只统计已删除内容，流量快照
按已处理的采样与份数计数。复制字节表示临时副本已写入，不表示最终目标已经发布。
跨卷移动区分复制与删除阶段；界面分别显示已复制到临时副本、已删除、已统计。

无法预先知道总量时（例如全盘文件数、复制一份大目录的字节总量），`total` 为 `null`：
界面显示不确定态进度条，**不伪造百分比**。「已运行 N 秒」是独立的等待信息，不是进度。

## 结果可信

- 完成、部分完成、失败、结果未知是四种不同状态；部分完成会带上逐项结果
  （完成/失败/跳过分别是什么），不把「删了一半」笼统说成失败。
- 请求超时或连接中断只表示结果未知：不提示成功、不提示失败、不自动重试。
- 服务重启会把上次遗留的运行中任务标记为结果未知，并说明需要重新读取目标核实。
- 同一请求标识只有在种类、展示目标、冲突锁与载荷指纹均匹配时才复用原任务；
  任一项不同都拒绝重放。
- 文件创建、改名、保存内容、复制、移动、删除与磁盘条目移到废纸篓共用文件域锁，
  保守串行写操作；访达定位不占写锁。
- 客户端先持久化待核实请求，再发送；保存失败时不发送。查询错误和 404 保留记录，
  只有已知终态才移除；结果未知保留记录，不自动重发。
- FRP 快速保存完成后更新提交内容的保存指纹；后台完成后读取真实指纹并保留当前草稿。
  读取失败明确提示状态未核实，刷新读取结束前不提示成功。
- 离线写请求在传输前拒绝，mutation 不暂停排队后重放；进行中写传输、mutation、
  待核实请求与后台任务阻止应用更新。
- 上传超时、中断、取消或不可信响应表示结果未知；同一页面会话内阻止同目标重传。
  目录核实只是只读观察，同名同大小不能证明本次上传成功。

- 真实子进程：进度与结果解析、失败与异常退出、中止、并发上限串行化。
- 磁盘扫描：真实计数与进度、文件名含换行不漏不重复、零结果拒绝报成功、
  不可读标记为不完整；端点 400/201/202/409/500。
- 流量快照：保存/合并/删除的落库与区间、非法载荷被拒；关联写入失败整批回滚，
  完成进度在提交后上报；端口采集超时和命令失败不冒充空结果。
- FRP：错误载荷在写入前拒绝；快速完成、后台终态、读取失败与草稿保留均有受控测试。

  临时副本未提前发布，失败清理不误删并发创建的目标。
- 删除磁盘快照：同一事务删除明细与快照、真实份数、已不存在时报 0。
- 前端：按钮 busy 与键盘不可触发、受理后 busy 延续到终态、终态只提示一次、
  离线停止轮询、恢复核实不重发；断网/404 保留未决记录，离线写操作未发送；
  上传未知结果不重传，应用更新在写传输执行期间被阻止。
- 通过真实 `createApp` 走 HTTP 的接线测试：任务端点确实挂在 `/api` 下、
  缺请求标识的写操作在动手前被拒、受理后能在任务里看到并在结束后拿到真实结果、
  同一请求标识只执行一次。测试禁用业务初始化，真实业务库、迁移与外部命令入口
  使用会抛错的替身，并验证没有调用；因此全量测试不启动真实流量采样。

## 统一机制的接入状态

已接入且具有对应联合结果契约：磁盘扫描、流量快照保存/合并/删除、文件复制/删除/移动、
创建/改名/保存内容、FRP 保存配置、磁盘快照删除。

系统服务动作（含该域的访达定位）、磁盘条目访达定位与移到废纸篓已有 handler、执行器
和单独结果 schema，但三个 schema 尚未纳入 `TaskRecordSchema` 联合契约。
这三类动作不能声明端到端接入完成；任务查询与结果解析存在缺口，已单独记录为整改项。

结束进程仍为即时请求，发送信号后的响应不等于进程已退出。流量页和端口页已有 busy
反馈与同步重复提交保护；不能据此声称所有进程入口均完成验收。

文件确认/编辑弹窗与 FRP、服务动作入口已有进行中反馈；请求未受理或失败时保留输入，
执行中禁用重复入口，后台受理不显示成功。登录页移除属于独立已授权变更，不回退。

## 未验证与明确限制

- 浏览器里的真实点击、手机触控目标与 PWA 安装、返回、恢复和更新行为；本轮未启动浏览器。
- 真实全盘扫描的耗时与内存表现；真实大目录复制/删除/跨卷移动的耗时。
- 系统服务与磁盘定位/废纸篓动作的联合结果契约缺口，及真实系统权限、launchctl 行为。
- 上传、下载是流式传输，不走后台任务机制；服务端没有可脱离传输查询的上传任务标识。
  上传未知记录和同目标保护只在页面会话内保存，不能承诺刷新或重启后恢复，且尚无上传页面入口。
- 目录核实不能证明上传身份与完整内容，也不自动解除未知结果保护。
- 构建仍有前端大包体积警告，不影响本次构建通过；未在本轮扩大范围处理。
